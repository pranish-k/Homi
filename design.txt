## 1. App Overview

**App Name:** Homi  
**Platform:** iOS (Swift)  
**Purpose:** A comprehensive roommate management app that helps housemates coordinate living together through messaging, expense tracking, location sharing, and chore management.

## 2. Core Features

### 2.1 Authentication System
- **Sign Up Methods:**
  - Apple Sign-In (required for iOS apps with social login)
  - Google Sign-In
  - Email/Password
  - Phone Number (SMS verification)
- **Login Options:** All sign-up methods available for login
- **Account Linking:** Users can link multiple auth methods to one account
- **Password Recovery:** Via email (for email/password users)
- **Profile Management:** Edit name, photo, contact info, linked accounts

### 2.2 House Management
- **Create House:** Set house name, address, invite code generation
- **Join House:** Enter invite code or accept invitation link
- **House Settings:** Edit house details, manage members, leave house
- **Member Roles:** House admin (creator) and regular members

### 2.3 Messaging System
- **Group Chat:** House-wide messaging with all members
- **Private Messages:** 1-on-1 conversations between housemates
- **Features:** Text, images, read receipts, push notifications
- **Message History:** Searchable chat history

### 2.4 Bills & Expense Management
- **Add Expense:** Amount, description, date, split type (equal/custom)
- **Track Payments:** Who owes whom, payment history
- **Recurring Bills:** Set up monthly utilities, rent, etc.
- **Settlement:** Mark payments as complete
- **Payment Integration:** Link PayPal/Venmo for in-app payments
- **Reports:** Monthly summaries, individual balances

### 2.5 Location Sharing
- **Toggle On/Off:** Privacy-first approach
- **Real-time Location:** When enabled, show on map
- **Location History:** Last known location with timestamp
- **Privacy Settings:** Individual control per housemate

### 2.6 Chores Management
- **Chore Calendar:** Visual calendar view
- **Create Tasks:** Name, frequency, assignee, due date
- **Rotation System:** Automatic assignment rotation
- **Reminders:** Push notifications for upcoming chores
- **Completion Tracking:** Check off completed tasks
- **Point System:** Optional gamification

### 4.2 Firestore-Optimized Data Patterns

#### Denormalization Strategy
Store frequently accessed data together to minimize reads:
- User names and photos in messages/expenses/chores
- Running balances in separate documents
- Member count in house document

#### Real-time Listeners
```swift
// Efficient listener setup
- House details: Single listener
- Recent messages: Limited query (last 50)
- Active chores: Where dueDate >= today
- Recent expenses: Last 30 days
- Member locations: Only if sharing enabled
```

#### Composite Queries
```swift
// Indexes needed for common queries:
- messages: (houseId, timestamp DESC)
- chores: (assignedTo, dueDate, isCompleted)
- expenses: (houseId, date DESC)
- payments: (fromUserId, timestamp DESC)
```

## 13. Firestore Implementation Guide

### Query Patterns & Best Practices

#### 1. **Efficient Data Loading**
```swift
// Load house data with members
let houseRef = db.collection("houses").document(houseId)
let membersRef = houseRef.collection("members")

// Use collection group for user's chores across houses
let myChores = db.collectionGroup("chores")
    .whereField("assignedTo", isEqualTo: userId)
    .whereField("isCompleted", isEqualTo: false)
    .order(by: "dueDate")
```

#### 2. **Real-time Listener Management**
```swift
// Set up listeners strategically
class HouseViewModel {
    // One-time fetch for static data
    func loadHouseInfo() { }
    
    // Real-time for dynamic data
    func listenToMessages() {
        // Only last 50 messages
        messagesListener = houseRef
            .collection("messages")
            .order(by: "timestamp", descending: true)
            .limit(to: 50)
            .addSnapshotListener { ... }
    }
    
    // Clean up on view disappear
    func detachListeners() {
        messagesListener?.remove()
    }
}
```

#### 3. **Batch Operations**
```swift
// Update balances after payment
let batch = db.batch()

// Update payer balance
batch.updateData([
    "totalOwed": FieldValue.increment(-amount)
], forDocument: payerBalanceRef)

// Update receiver balance  
batch.updateData([
    "totalOwes": FieldValue.increment(-amount)
], forDocument: receiverBalanceRef)

// Create payment record
batch.setData(paymentData, forDocument: paymentRef)

// Commit all at once
batch.commit()
```

#### 4. **Offline Support**
```swift
// Enable offline persistence
let settings = FirestoreSettings()
settings.isPersistenceEnabled = true
settings.cacheSizeBytes = 50 * 1024 * 1024 // 50MB
db.settings = settings
```

### Security Rules

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    
    // Users can read/update their own profile
    match /users/{userId} {
      allow read: if request.auth != null;
      allow write: if request.auth.uid == userId;
    }
    
    // House access only for members
    match /houses/{houseId} {
      allow read: if request.auth.uid in resource.data.memberIds;
      allow update: if request.auth.uid in resource.data.memberIds
        && request.auth.uid == resource.data.createdBy;
        
      // Subcollections inherit house permissions
      match /{subcollection}/{document} {
        allow read: if request.auth.uid in 
          get(/databases/$(database)/documents/houses/$(houseId)).data.memberIds;
        allow create: if request.auth.uid in 
          get(/databases/$(database)/documents/houses/$(houseId)).data.memberIds;
        allow update: if request.auth.uid in 
          get(/databases/$(database)/documents/houses/$(houseId)).data.memberIds
          && (request.auth.uid == resource.data.createdBy || 
              request.auth.uid == resource.data.assignedTo);
      }
    }
    
    // Invite codes are public read with code
    match /invites/{inviteCode} {
      allow read: if true;
      allow write: if false; // Only through Cloud Functions
    }
  }
}
```

### Cost Optimization Tips

1. **Use Compound Queries**
   ```swift
   // Bad: Two separate queries
   let owedExpenses = expenses.whereField("paidBy", isEqualTo: userId)
   let owesExpenses = expenses.whereField("splits.userId", isEqualTo: userId)
   
   // Better: One query with local filtering
   let allExpenses = expenses.whereField("date", isGreaterThan: thirtyDaysAgo)
   ```

2. **Cache Expensive Calculations**
   ```swift
   // Store monthly summaries instead of calculating
   /houses/{houseId}/summaries/{yearMonth}
   ```

3. **Paginate Large Collections**
   ```swift
   func loadMoreMessages() {
       query = query.start(afterDocument: lastDocument).limit(to: 25)
   }
   ```

4. **Use Local State**
   ```swift
   // Don't refetch user profile repeatedly
   class UserManager {
       static let shared = UserManager()
       private var cachedProfile: User?
   }
   ```
